# Agent-Based Financial Market Simulation (2003) — presentation site

A small static website presenting Chapter 2 of Nicolas Boitout's doctoral
dissertation, defended in 2003 and written in English with Thierry Delahaut: an
agent-based microsimulation of the foreign-exchange market in which trading time
itself is random.

The site presents the 2003 work as it was. It does not modernise the model, add
critique, or correct it. Every figure on it was produced by a re-implementation
written in 2026 from the chapter's own equations, and says so.

```
engine/model.mjs        the model — the only place the equations live
engine/generate.mjs     build step: runs the model, writes data/*.json
engine/build-site.mjs   build step: renders the maths, vendors KaTeX, builds the page
data/                   the generated series (archival JSON)
site/                   the deployable site
source/                 the translated chapter and the original Figure 2.1
```

## Building

```bash
npm install              # KaTeX only; nothing else is required at runtime
node engine/generate.mjs # regenerates every published figure's data
node engine/build-site.mjs
```

`site/` is then a complete static site. It has no server, no database, no
analytics, no third-party requests, and works when opened from disk as well as
when served. To serve it locally:

```bash
python -m http.server 8123 --directory site
```

## Regenerating the figures

Every published figure comes from one run at one fixed seed. The whole of it is
regenerated by:

```bash
node engine/generate.mjs
```

The canonical run is 2,500 simulated days at seed `20030601`, set at the top of
`engine/generate.mjs`. It takes about a second and writes:

| File | Feeds |
|---|---|
| `data/run.json` | price and fundamental chart, returns spike plot |
| `data/derived.json` | distribution, autocorrelations, volatility-against-volume scatter, summary statistics |
| `data/microstructure.json` | the ten-clocks figure, the business-time staircase |
| `site/assets/og.png` | the Open Graph card (the price chart, written as a PNG by hand) |
| `site/assets/hero-still.svg` | the still shown in place of the hero animation under `prefers-reduced-motion` |

Each payload is written twice: as JSON under `data/`, which is the archival
copy, and as a one-line script under `site/data/`, which assigns the identical
object to a global. The page loads the second form so that it also works from a
`file://` origin, where `fetch` is not permitted. Total payload is about 110 KB.

`engine/build-site.mjs` additionally generates `site/sim-core.js` from
`engine/model.mjs` by stripping the module exports. That file is loaded both by
the page and by the Web Worker, so the simulation a visitor watches in the
dashboard and drives in the playground is running the same equations the
published figures came from, differing only in population size and run length.
Do not edit `site/sim-core.js`: edit the model and rebuild.

## The live panels

`site/sim-driver.js` drives the model for the two live panels, in two modes.

**`daily`** feeds the playground. It advances whole simulated days and records
each day's closing price, which is the chapter's own recording rule. Someone
moving a slider wants to see weeks of consequence.

**`tape`** feeds the dashboard at the top of the page. It advances about four
hundredths of a day per frame and records *every* event as it happens, so the
price line, the population band and the event raster all sit on one shared axis
of simulated time and can be read against each other: the price steps only where
the raster shows a price event, and both go quiet together. That is the point of
the dashboard — the irregularity of trading time is the chapter's distinctive
claim, and it is visible in the first second rather than only described in §2.2.5.

The window is two simulated days on a desktop and about one on a phone, because
a raster is only worth drawing while its gaps are still separable: at 320px a
two-day window would pack nine hundred events into a solid band. Under
`prefers-reduced-motion` the whole dashboard is replaced by the pre-rendered
still in `site/assets/`.

## What was available, and what was not

The source is `source/chapter2-translation.txt`, an English translation of the
chapter's manuscript pages, together with `source/figure-2-1-original.png`, the
original Figure 2.1.

Three gaps matter, and the site states all three:

1. **The chapter's results sections were not part of the material.** Its
   estimated tail indices, long-memory parameters, BDS statistics and structure
   functions are therefore unavailable. No number is attributed to them anywhere
   on the site. Every number shown comes from the re-implementation.
2. **Original pages 69–71 were not supplied.** The translation marks the gap and
   resumes mid-sentence on page 72. Table 2.1 and the implementation notes of
   §2.3 were supplied separately in the build brief and are transcribed as such.
3. **Two citation placeholders**, rendered `44` and `444`, remain unresolved in
   the translated text. They are shown as unresolved rather than guessed at.

## Readings taken from the source

Three places in the chapter are either ambiguous or silent, and the
implementation had to choose. Each choice is recorded here and stated on the
page; none is a correction of the paper.

**1. The momentum term inside U₁.** The source gives

> U₁ = α₁x + (α₂/ν₁) · [p(t) − p(t−τ)] / τ

with the momentum term in absolute price units. At the Table 2.1 values and a
fundamental of 100, that term reaches magnitudes above 20; the exponential
transition rates then overflow, one chartist camp empties to its floor within a
simulated day, and the internal clock stops advancing. The term is read here as
a rate of return rather than a price change — divided by `p`, exactly as the same
momentum signal is written inside U₂,₁ and U₂,₂ in the source, and as the
scale-free opinion index it is added to requires.

**2. The market maker's rate.** The chapter gives the market maker's behaviour
twice: as jump rates linear in excess demand, β₇ = β·ED and β₈ = −β·ED, in the
list of rates; and as P(·|ED) = exp(β·ED) in the pricing-rule section. The second
form is not a probability — it exceeds one for positive excess demand — and
diverges at the excess demands this population generates. The linear rate from
the list of jump rates is used, with only the rate in the direction of the
imbalance live at any moment.

**3. γ and t_f.** Excess demand is written with a fundamentalist reaction
strength γ; Table 2.1 publishes `t_f = 3.0` alongside the chartists' `t_c = 0.1`
and no γ. The two are taken to be the same quantity.

## Values the model needs that Table 2.1 does not publish

The chartists' look-back horizon τ, the foreign rate `r`, and the floor imposed
on each strategy's share of the population are all used by the model and none
appears in the published table. The values used here are illustrative, and the
site says so wherever they affect a figure.

| | Used | Why |
|---|---|---|
| τ | 3 days | Chosen by the chapter's own first calibration step — a graphical screen for non-pathological dynamics. See below. |
| `r` | 0.0004 | Set equal to the domestic rate `R`, that is, a zero interest differential. In the source `r` enters divided by `p`, so its magnitude is immaterial. |
| population floor | 10% per strategy | The chapter states that a minimum was imposed to prevent the absorbing states in which the whole population holds one strategy, but does not publish its value. |

τ and the floor were chosen by sweeping both against six random seeds and
keeping the combinations that produced non-pathological dynamics at every seed —
bounded prices, FX-like daily volatility, and a mispricing that does not run
away. At a 1% floor the model explodes for two seeds in six regardless of τ; at
10% it is stable across the sweep. This is the chapter's step one, and the
sensitivity is consistent with what the chapter itself reports about the need
for substantial fine-tuning.

## Measurement definitions

The chapter names the quantities it wants reproduced but does not give operating
definitions for all of them. Those used here:

- **Returns** are daily log differences of the recorded closing price, in per
  cent. The closing rule is the chapter's own: when the internal clock crosses a
  day boundary, record the price.
- **Volatility** is the absolute return.
- **Volume** is the gross size transacted against the market maker, accumulated
  over the day: at each price revision, every chartist's unit order plus every
  fundamentalist's order, which scales with the mispricing. The chapter
  distinguishes order flow, which measures transactions actually executed, from a
  change in demand, which need not imply a transaction; volume is therefore
  accumulated at the moment of a transaction. Counting revisions alone, without
  their size, is a poorer measure in this implementation: the tick is discrete, so
  the number of revisions tracks the size of the fundamentalist population rather
  than the size of the day's price move.
- **Autocorrelation** at lag *k* is the ordinary sample correlation of a series
  with itself shifted by *k* days.

## Choice of stack

Plain HTML, CSS and JavaScript, with two Node scripts as the build. No framework,
no bundler, no client-side router. The site is a document with charts, and a
framework would have added a build graph and a runtime to a page that needs
neither. The consequences are worth stating: the page loads about 40 KB of its
own JavaScript, renders no maths at runtime because KaTeX runs at build time,
makes no network request to any third party, and opens correctly from the
filesystem. The charts are hand-rolled SVG, with one canvas for the 2,500-spike
return plot where SVG would be wasteful.

## Accessibility

Real heading hierarchy with one `h1`; every control keyboard-operable with a
visible focus ring; every figure carries a `<title>` used as its accessible
description, and the results gallery additionally has the five figures as data
tables behind a disclosure. `prefers-reduced-motion` replaces the hero animation
with a pre-rendered still and leaves the playground paused until it is started
explicitly. Both themes follow the visitor's system setting with a manual
override.

## Deployment

Pushing to `main` triggers `.github/workflows/pages.yml`, which installs
dependencies, runs `npm run build`, drops the development contact sheet and
publishes `site/` to GitHub Pages:

> https://nboitout.github.io/PhD_Microsimulation/

The workflow rebuilds rather than trusting the committed output. That is
meaningful because `engine/generate.mjs` is deterministic: at its fixed seed,
two runs produce byte-identical `data/*.json` apart from the build date. If the
committed data or page ever drift from what the engine and `index.src.html`
produce, the rebuild is what gets published, and `npm run build` locally brings
the committed copies back into line.

Every path the page loads is relative, so the site works at a project subpath,
at a domain root, and from the filesystem alike. The only absolute URLs are the
two Open Graph tags, which social-card scrapers will not resolve otherwise; if
the site moves, those two lines in `site/index.src.html` are what need changing.

## Not part of the published site

`site/_figures-preview.html` renders one figure at a time for development
(`?f=price,returns,dist,acf,scatter,strategies,clock,biztime,tick`). The Pages
workflow deletes it before publishing.
